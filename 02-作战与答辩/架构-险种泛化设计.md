# 架构：险种泛化设计（为什么换一个险种不用重写智能层）

> 写于 2026-10-06 深夜。起因：调研发现 GitHub 上已有一批同题项目，其中几个的险种覆盖 AQI / 高温 / 台风 / 平台宕机。
> 因此需要回答两个问题：**① 能不能抄它们的 AI？② 我们的架构能不能扩到别的险种、要花多少？**
> 本文只写**已用代码核实过的事实**与**工时估计**，不写愿景。

---

## 一、结论（三句）

1. **抄它们的 AI 不可行，也不需要**：那些仓库是「README + 架构图」，「AI」是文字描述，没有模型文件、没有训练数据、**没有 LICENSE**（默认保留所有权利）。更关键的是，它们的判定**必须**吃平台订单数据与 GPS 轨迹（见 §二），而那正是我们刻意不依赖的东西。
2. **真正省事的那次「复用」，我们已经在代码里做完了**：上游数据源是**同一个 API 家族**（Open-Meteo 一个站点同时给降水/气温/风速/空气质量），而我们的**判定规则、哈希纪律、判定注册表、赔付路径本来就是险种无关的**。锁死成「雨」的只有**字段命名与常量**，不是智能。
3. **扩领域的瓶颈不在 AI，在合约 + 证据链**：改险种 = 重部署 + 重跑 73 项合约回归 + 重建全部链上证据。**10/8 12:00 之前做这件事，是拿交付物换 PPT。**

## 二、复用可行性：逐条证据

| 项目 | 仓库里实际有什么 | 「AI」实际是什么 | 为什么不能抄 |
|---|---|---|---|
| [Hypernova-DevTrails26/FluxShield](https://github.com/Hypernova-DevTrails26/FluxShield)（Guidewire DevTrails 2026 Phase 1） | 19 个提交；文件 = `backend/ react-app/ app.js server.js mockapi.js styles.css index.html` + **9 张 PNG 架构图**；无 LICENSE | README 写 **XGBoost（风险预测）/ 回归（收入损失估计）/ Isolation Forest（反欺诈）**，但仓库里**没有模型文件、没有训练数据、没有权重**；官方自述 `Phase 1 Concept and architecture complete` | ① 无 LICENSE = 不能合法复制；② 「AI」是 PPT 级描述；③ 它的反欺诈叫 **Proof-of-Work**，要求**平台订单日志 + 近 30 分钟 GPS 轨迹 + App 前台状态** |
| [ayveHacks/parametric-insurance](https://github.com/ayveHacks/parametric-insurance) | **是 [psweb26/QuickCommerce-InsuranceAi](https://github.com/psweb26/QuickCommerce-InsuranceAi) 的 fork，全部只有 4 个提交**；仓库内容 = `docs/` + `README.md` + `requirements.txt` | README 声称 AI 做风险预测/动态定价/异常检测，但 README 里写的 `src/ frontend/ backend/` 目录**在仓库里根本不存在** | ① 同样无 LICENSE；② 判定式明写在 README：`WorkLossRatio = (ExpectedOrders − ActualOrders) / ExpectedOrders ≥ 0.5 → 批准`，**直接依赖平台订单数** |

**共同点（这才是重点）**：它们的「自动赔付」在架构上都是**后端说了算** —— FluxShield 的即时赔付是后端调 Razorpay（UPI），ayveHacks 的判定是 Flask 算一个比率。
→ **抄进来不但不省事，还会把我们最硬的卖点（不依赖平台数据、骑手不举证）换成我们最怕的依赖。**

> 附带风险：手册 L205 要求提交时「注明活动期间新增内容」，提交材料要「注明沿用组件来源」。用**另一场黑客松（Guidewire DevTrails 2026）**的提交物，被查出来是灾难。

## 三、我们自己的「二次开发」已经做对了：险种无关的边界

> 事实来源：`03-合约/RainDeliveryInsurance.sol`、`04-脚本/ai-collect.js`、`04-脚本/ai-judge.js`（已逐行核实）。

### 3.1 合约层

| 已经险种无关（换险种可原样复用） | 锁死成「雨」的部分 |
|---|---|
| `submitJudgement(uint256 policyId, uint8 decision, uint8 confidence, bytes32 inputHash, bytes32 outputHash, string modelVersion)` | `sol:20-24` 五个 `constant`：`PREMIUM` / `PAYOUT` / **`THRESHOLD = 50`** / `MIN_HOURS` / `MAX_HOURS` —— **构造时不可配，`THRESHOLD` 写死** |
| `struct Judgement { kind, decision, confidence, sources, judgedAt, exists, inputHash, outputHash, modelVersion }` —— **没有任何字段叫"雨"** | `struct Policy { …, uint256 rainfallAtBuy }`（`sol:55`） |
| `MIN_CONFIDENCE` / `KIND_FEED` / `KIND_LOSS` / `DECISION_DENY` / `DECISION_PAY` | `rainfall(uint8)` / `rainfallDuring(uint256)` 两个 getter |
| `setUnderwriting(uint8 regionId, uint8 level, uint256 premium, bytes32 reasonHash)` —— **每区域独立保费，本身就是多险种的挂载点** | `event RainfallUpdated(regionId, cumulativeMm, evidenceHash, confidence, reporter)` |
| `claim(policyId)`（无权限修饰符）/ `keeper.js` / 资金池 / `reserve` | `KIND_LOSS` 的中文注释口径（「这场雨有没有砸在人身上」） |

### 3.2 AI 判定层

| 已经险种无关 | 锁死成「雨」的部分 |
|---|---|
| `04-脚本/ai-judge.js:52-110 decide()` 的 **R1–R5**：只看 `official` / 三个模型值 / `threshold` / `spread` / `med` / `agreeCount` / `divergencePct` —— **不知道自己在判什么天气** | `04-脚本/ai-collect.js:88` 与 `:94` 两处写死 `&daily=precipitation_sum` |
| `04-脚本/canonical.js` 的哈希纪律（递归排序 + 定点舍入） | `:104` `precipitation_sum_${m.id}` 取字段 |
| `04-脚本/submit-judgement.js` 提交 + 6/6 读回校验 | `:54-56` ABI 里的 `rainfall` / `rainfallDuring` / `rainfallAtBuy` |
| keeper 的「遍历保单 → 只赔 `claimable`」逻辑 | `:199-216` 快照字段名 `cumulativeMm` / `officialIncrementMm` / `thresholds.thresholdMm` |

**一句话**：换险种要改的是「**取哪个变量 + 字段叫什么 + 阈值常量**」，**判定规则与哈希纪律一行都不用动**。

## 四、可扩展的方向：数据源其实同一家

| 险种 | 触发量 | 数据源 | 阈值示例 | 政策 / 先例锚点 |
|---|---|---|---|---|
| 极端降雨（**已有，已上链**） | 72h 累计降水 | Open-Meteo `archive-api` + `forecast`（3 模型） | ≥ 50 mm（国标 24h 暴雨线） | 万宁东星斑气象指数保险（日降水 ≥50mm 触发） |
| ⭐ **高温** | 日最高气温 | Open-Meteo **同一个 forecast 接口**，`daily=temperature_2m_max` | ≥ 40 ℃ | **人社厅函〔2025〕113 号：≥40℃ 停止室外露天作业** ← 最硬的政策锚，且明确点名外卖骑手 |
| 空气污染 | PM2.5 / AQI | Open-Meteo `air-quality-api`（**同一家、免费**） | PM2.5 ≥ 150 μg/m³ | 印度同类项目用 AQI > 400（当地口径） |
| 台风 / 大风 | 10m 最大风速 | Open-Meteo 同接口 `daily=wind_speed_10m_max` | ≥ 17.2 m/s（8 级） | 万宁险同口径（大风 ≥17.2 m/s） |
| 寒潮 | 日最低气温 | 同接口（**判定方向要反过来**） | ≤ −10 ℃ | —— |
| 洪水 / 内涝 | 水位 / 预警级别 | 水利部或地方预警 API —— **需授权，不是免费开放数据** | 橙色预警及以上 | 2023 台风「杜苏芮」温州巨灾指数保险即刻赔付 |
| 平台宕机 | uptime 探针 | 需平台配合或公开状态页 | 连续中断 ≥ N 分钟 | —— |
| 交通管制 / 封路 | 官方管制公告 | 需官方授权（文本源，引入人工判断） | —— | —— |
| 夜间 / 人身安全 | 个人行为数据 | **需要个人数据** | —— | **不建议**：会破坏「不依赖个人数据、骑手不举证」这条卖点 |

**成本阶梯**：**同源换变量（便宜）→ 换数据方（要授权、要周期）→ 要平台/个人数据（卖点崩塌）**。
前 5 个险种全在 Open-Meteo 一家；第 6 个开始才需要新的数据方。

## 五、工作项与工时（诚实估计）

### L1 · 判定层加一个险种 —— 约 1～1.5 小时/险种（可当晚做，零风险）
- `04-脚本/ai-collect.js`：抽出 `PERILS` 表（`peril → endpoint + daily 变量 + 单位 + 判定方向`），`fetchModels()` 改成读表；加 `--peril=` 参数；快照字段改成通用名（保留 `rainfall` 的兼容读取）。
- `04-脚本/ai-judge.js`：R1/R5 加**方向**（`above` / `below`）。其余不动。
- `07-测试工具/check-ai.js`：加断言（换险种后规则仍满足 60 分门槛；方向反转时 DENY/PAY 正确翻转）。
- **不动合约，不动任何已上链的东西。**

### L2 · 合约层险种化 —— 约 4～8 小时，**且必须重建证据链**（不建议在截止前做）
- 把 `sol:20-24` 的常量提到构造函数或 per-peril 配置（`THRESHOLD` 目前写死）；
- `Policy.rainfallAtBuy` → 通用字段（如 `metricAtBuy` + `metricCode`）；`RainfallUpdated` → `MetricUpdated(regionId, metricCode, value, …)`。
- **连带代价（这才是真实成本）**：重新部署 → 重跑 `07-测试工具/e2e_contract.js` 73 项 → 改演示页与核验台的 ABI 解码 → **重建 `02-作战与答辩/汉客松-交易哈希清单.md` + `08-截图存证/真链留痕-2026-10-06.md` + AI 判定留痕的 inputHash/outputHash** → 所有已提交材料里的地址与哈希全部作废。
- **判断**：10/8 12:00 前做这个 = 用已经跑通的证据换一个 PPT 上的多险种。

### L3 · 接新数据方 —— 每个 1～3 小时 **+ 申请周期**
- 洪水/内涝、交通管制这类没有免费开放接口的：要么申请授权（来不及），要么改用「预警级别」文本源（**引入人工判断，破坏自动化与可复算**）。
- **结论**：新数据方的成本不在代码，在**授权与人工环节**，这两样都会削弱可验证性。

## 六、区块链作为核心差异点：当场可验的五条

| # | 差异点 | 代码/链上事实 | 怎么当场验 |
|---|---|---|---|
| 1 | **判定哈希上链 + 可被第三方逐字节复算** | `Judgement.inputHash/outputHash`；`04-脚本/canonical.js` 的排序+定点舍入 | `node 07-测试工具/check-ai.js`（29 项，含"仓库里每条留痕的哈希都能当场重算"）；重跑 `ai-judge.js` 比对 `outputHash` |
| 2 | **喂价即事实**：输入也上链 | `event RainfallUpdated(regionId, cumulativeMm, evidenceHash, confidence, reporter)` | 粘喂价交易哈希到核验台 |
| 3 | **无权限赔付**：不需要运营方按键 | `03-合约/RainDeliveryInsurance.sol:243` `function claim(uint256 policyId) external notPaused`（**无权限修饰符**）+ `04-脚本/keeper.js` 自动扫 `claimable` 并赔付 | 真链跑 `node keeper.js --dry-run`；历史上有 keeper 实际赔付的 tx |
| 4 | **资金池与准备金在链上** | `poolBal` 实时读；`reserve` + `withdrawPool` 守卫 | 演示页「资金池」数字；`reserve` getter |
| 5 | **全链审计轨迹** | 11 个事件（`PolicyBought`/`RainfallUpdated`/`JudgementSubmitted`/`ClaimPaid`/`UnderwritingDecision`…），合约至今 26 条日志 | 核验台粘合约地址 → 表格逐条解出人话 |

> **对比一句话**：FluxShield 的「即时赔付」是后端调 Razorpay；ayveHacks 的判定是 Flask 算一个比率；**同样是「自动赔付」四个字，只有我们是第三方可以复算的。**

## 七、现在该做什么（取舍）

- ❌ **不要动合约**（L2）。截止前第一优先级是交付物与证据。
- ✅ **要做（约 30–60 分钟，零风险）**：就是本文 —— 答辩被问「能不能扩展到别的场景」时，直接给 §三 的两张 seam 表 + §四 的数据源表。**这张表比任何 PPT 都硬：我们的智能层本来就是险种无关的，锁住的只是命名与常量。**
- ⚠️ **可选（10/7 下午若有 1 小时）**：只做 L1，在本地链上跑通「高温」险种到判定上链（`--peril=heat`），作为**泛化能力的实证**；快照里记 `peril: "heat"`。做不完不影响交付。
- 📌 **答辩话术**：
  > 「我们确实读过很多别人做过的同题项目 —— 它们证明方向是对的，但它们把信任押在自己的后端上。我们把信任押在一条**任何人都能复算**的链上。而且换险种不用动我们的智能层：判定规则 R1–R5 只看『链上的值、三个模型的值、阈值、离散度』，它根本不知道自己在判什么天气；锁死成雨的只有字段名和那个 50。」
